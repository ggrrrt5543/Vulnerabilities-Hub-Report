# Hub: отчёт по безопасности и примеры исправлений

Материалы по контролю доступа к API приложения Hub (`org.hubnet.android`): описание заявленных проблем, учебные исправления и локальные регрессионные тесты.

> Это не исходный код сервера Hub и не готовое обновление его инфраструктуры. Наличие уязвимостей на действующем сервисе в рамках этой работы не проверялось. Примеры необходимо адаптировать к реальной схеме данных, системе авторизации и политике приватности.

## Что описано в исходном отчёте

| Проблема | Уровень из исходного отчёта | Маршрут | Требуемая защита |
| --- | --- | --- | --- |
| Доступ к сообщениям чужого чата, IDOR | Критический | `GET /api/message/{chatId}` | Проверять участие пользователя в чате |
| Доступ к закрытому профилю, IDOR | Средний | `GET /api/profile/{publicId}` | Проверять владельца и настройки публичности |
| Доступ к метаданным чужого чата, IDOR | Средний | `GET /api/chats/{chatId}` | Проверять участие и ограничивать состав ответа |
| Определение существования аккаунта | Низкий | `POST /api/auth/password/request-code` | Унифицировать ответы и исключить зависимость HTTP-обработчика от наличия аккаунта |

Эти уровни не являются рассчитанными оценками CVSS. Для подтверждения нужны разрешённое воспроизведение, матрица прав, фактические ответы сервера и оценка влияния. Сам по себе просмотр чужого **публичного** профиля не доказывает IDOR: решающей является политика доступа.

Исходный текст также утверждал, что проверки RCE, XSS, CSWSH, SSRF и подмены автора не выявили проблем. В репозитории нет достаточных доказательств, чтобы независимо подтвердить эти выводы. Конвертация изображения в WebP, например, сама по себе не доказывает отсутствие RCE.

## Быстрая локальная проверка

Нужны Python 3.11 или новее, Node.js 22 или новее и Bash. В рамках проверки использованы Python 3.13 и Node.js 24. Команды ниже не обращаются к Hub.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-lock.txt -r requirements-dev.txt
npm ci --ignore-scripts

python -m pytest -q
python -m compileall -q fixes poc tests
bash -n poc/idor_messages.sh poc/idor_profile.sh
npm run check
npm test
```

Тесты используют SQLite, эмулятор Redis, подставные ответы CAPTCHA и модель PostgreSQL-запроса. Проверка маршрута профиля идёт по HTTP только на `127.0.0.1`. Что именно подтверждено и что осталось непроверенным, указано в [отчёте проверки](CODE_REVIEW.md).

## Как устроены примеры

- **Сообщения и метаданные:** Flask проверяет JWT, состояние сессии и членство в чате; пагинация ограничена и упорядочена.
- **Профиль:** Express использует параметризованный SQL и возвращает только разрешённые поля.
- **Восстановление пароля:** любой допустимый адрес передаётся в очередь, HTTP-обработчик не ищет пользователя в БД.
- **Токены:** refresh обновляется атомарно через Redis; повторное использование отзывает семью токенов одной сессии.
- **CAPTCHA:** проверяется сервером; ошибки провайдера и несовпадение имени хоста приводят к отказу.
- **Socket.IO:** токен передаётся в пакете подключения, а авторизация и членство проверяются повторно перед записью сообщения.

Flask, Express и Socket.IO здесь — самостоятельные примеры подходов, а не требование одновременно внедрять три сервера. Функции доступа к очереди, БД, сессиям и отправке сообщений передаются извне. Они не подменены пустыми `pass` и не являются готовой интеграцией с Hub.

## Проверка на разрешённом стенде

Скрипты в `poc/` используют существующий формат cookie `x-session-token` из исходного описания. Учебные JWT-маршруты используют `Authorization: Bearer ...`; это разные протоколы, автоматически совместимыми они не становятся.

Скрипты не содержат действующего адреса Hub, токенов, чужих идентификаторов или адресов электронной почты. Для запуска необходимо явно задать `BASE_URL` собственного разрешённого стенда. Токен задаётся переменной `SESSION_TOKEN`, а не аргументом командной строки. Не сохраняйте его значение в истории команд или журналах CI.

```bash
# BASE_URL и SESSION_TOKEN заранее заданы безопасным способом.
bash poc/idor_messages.sh ИДЕНТИФИКАТОР_ТЕСТОВОГО_ЧАТА
bash poc/idor_profile.sh ПУБЛИЧНЫЙ_ИДЕНТИФИКАТОР
python poc/enum_emails.py registered@example.test missing@example.test
```

Скрипты IDOR выводят только код HTTP, а не содержимое переписки или профиля. Скрипт сравнения адресов делает ровно два запроса и не объявляет аккаунт существующим по одному коду HTTP. Эти сценарии не входят в тесты действующего сервиса.

## Важное о секретах

В прежнем README присутствовали строки, похожие на session-токены. Из текущих файлов они удалены, однако старые коммиты могут их сохранять. Если токены были настоящими, их нужно немедленно отозвать; удаление из последнего коммита не заменяет отзыв. При необходимости отдельно очистите историю репозитория и проверьте копии и форки.

## Границы применения

Публикация этих материалов на GitHub не означает исправление сервера Hub. Проверяйте только собственные системы или системы с явным разрешением владельца. Не публикуйте переписку, персональные данные и рабочие секреты. Подробности — в [SECURITY.md](SECURITY.md).
